# index.html リニューアル設計（housemind.net参考）

## 背景・目的

aidandaide.com のトップページ（index.html）を、参考サイト housemind.net（ハウスマインド株式会社）の雰囲気に寄せてリニューアルする。

当初「housemind.netのような温かみのあるベージュ×角丸×写真中心のデザイン」を想定していたが、実際にブラウザでhousemind.netを確認した結果、実態は白背景・シャープな矩形・ブルーのアクセント・実写真を全面に使った編集的なレイアウトであることが判明した。これは現状のaidandaide.comが持つ「罫線・グリッド・極太タイポ・番号振り」という骨格と親和性が高く、今回のリニューアルは**現状の構造を活かしたまま、実写真とアクセントカラーの変更を行う**方向で進める。

途中、ラウンド型の配色ミックス案（ネイビー×ブルー×イエロー×ピンクのパステル案）を提示したが、「AI生成っぽい」との強いフィードバックを受けて撤回し、housemind.net実物に基づいた方向へ再設計した経緯がある。

## 対象範囲

- `index.html` のみ。`mikke.html` / `biz_aid.html` は対象外（今回は着手しない）。

## 1. レイアウト・構造

現状の構造をベースに維持する。変更するのは以下の2箇所：

- **ヒーロー部分**（`.hero`）：現状は左にテキスト、右に3つのサービスメニュー（`.hero-r` / `.hero-svc`）のみ。右側のメニュー部分に実写真を組み込む形に変更する。3つのサービスメニュー自体（集客支援ミッケ！UGC / 生成AIツール作成 / 伴走コンサルティング）はテキストとして残す。
- **実績セクション**（`.case-list` / `.case-item`）：現状は文字のみのケースカード（Case 01〜07）。対応する業種の実写真をカード内に追加する（`.case-meta` 部分に写真パネルを追加、もしくはカード左端に写真列を追加）。

その他のセクション（NUMBERS, UGC, PROBLEM, SERVICES, AI TOOLS, WHY US, TEAM, FLOW, CONTACT, CTA, FOOTER）は、罫線・グリッド構成そのものは変更しない。角丸は導入しない（housemind.net自体も角丂なしのシャープなデザインのため）。絵文字アイコン（`.ugc-icon` 内の⭐📱💬）は現状維持でよい（今回の「AI感」批判は色・レイアウトへの言及であり、既存の絵文字使用について変更要望は出ていない）。

## 2. 配色

現状のCSS変数を変更する：

```css
:root{--ink:#303030;--red:#E31E23;--mid:#808080;--faint:#E8E8E8;--bg:#ffffff}
```

これを以下の方向に変更：

- `--ink`（見出し・本文の基調色）→ ネイビー `#1B2A4A`
- 新規変数としてブルー `#3A7BD5` を追加し、リンク・ラベル・ホバー・アイコン色など、現状 `--red` が使われていた装飾的な用途に充てる
- `--red`（`#E31E23`）は**削除しない**。ロゴ画像（`.nav-logo img`）はbase64埋め込みの既存画像であり変更しないため、ロゴ周りでのみ赤が視覚的に残る。CSS上の `.nav-cta:hover` や `.btn:hover` など、これまで赤に切り替わっていたインタラクションは、ブルーもしくはネイビーの濃淡に置き換える。
- 背景 `--bg: #ffffff` は変更しない（白背景を維持）。角丸なし、細罫線 `--faint:#E8E8E8` は維持。

具体的な置き換え箇所は実装計画（plan）側で洗い出す。CSS変数を差し替えるだけで多くの箇所は連動して変わる設計になっている（`--red` を参照している箇所を確認し、ロゴ以外の用途はブルー/ネイビーに置き換える）。

## 3. 写真

Unsplashの無料写真（Unsplash License、商用利用可・帰属表示任意）を採用する。実装時に画像をダウンロードし、リポジトリ内に配置する（`images/` ディレクトリを新設し、base64埋め込みではなくファイル参照にする — 既存のbase64埋め込みが原因でReadツールでの全文読み込みがトークン上限に達する問題があるため、新規画像はこの問題を再現しない方式にする）。

採用する4枚：

| 用途 | 説明 | Unsplash画像ID/URL |
|---|---|---|
| 居酒屋・BAR（2軒目需要） | 酒瓶の並ぶバーの前に立つ店主 | `https://images.unsplash.com/photo-1730297221520-edb32650e0ba` |
| 工務店・職人 | 窓辺で工具を研ぐ職人 | `https://images.unsplash.com/photo-1566453838084-7ec27e71b3ca` |
| 女性店主のカフェ | 明るいカフェでコーヒーを淹れるバリスタたち | `https://images.unsplash.com/photo-1749813387632-046a0a68c0fc` |
| キッチンカー | 屋台の前に立つ人 | `https://images.unsplash.com/photo-1704820505492-3713586e2bd1` |

**写真なしで進める業種**：車屋（自動車整備・コーティング）、不動産、士業（税理士等）。日本人と明確にわかる・業種にマッチする無料写真が見つからなかったため、この3業種のケースカードはアイコン＋テキストのみとする。将来的に有料素材購入や実際の顧客写真が揃った時点で差し替え可能な構造にしておく（画像なしでもレイアウトが崩れないようにする）。

この4枚をどのケース（Case 01〜07）に当てるかの対応表は、実装計画時に既存の業種（美容室、不動産、工務店、税理士事務所、飲食/居酒屋、パーソナルジム、NPO）と照らし合わせて決定する。少なくとも「工務店」「飲食（居酒屋）」には上記のM・G写真をそのまま当てられる。カフェ・キッチンカー・BARに該当する既存ケースがなければ、ケース内容自体の業種を差し替えるか、新規ケースとして追加するかを実装計画で判断する。

## 4. コピー（文章）

現状のindex.html内の見出し・本文・ラベルは、ユーザーから「全てがAI感がある」と明確なフィードバックを受けた。書き直しの方針：

- **トーン**：会話調・人の声に近い表現を採用する（ユーザーが選択した方向）。例：「うち、口コミが全然集まらなくて。そんな悩み、一緒に解決します。」のような、話し言葉に近い自然な口語調。
- **避けるべきパターン**：
  - 英語・カタカナ交じりのラベル（例：`UGC MARKETING × AI DISCOVERY`）
  - 過度に整った三分割構成やバズワード（`仕組み化`, `伴走`, `LLMO`, `全方位` 等の多用）
  - 抽象的な決め台詞（「だから私たちは『全方位で設計する』。」のような、内容の伴わない強調文）
- 書き直し対象：hero見出し・サブコピー、各セクションの `.sh-label` 英字ラベル、`.svc-intro`、`.whyus-p` 等の本文。数値データ（10年、53社+等）や具体的な事実情報（Formspree設定、料金等）はそのまま維持する。
- 書き直しの具体的な文面は実装計画・実装フェーズで作成し、都度ユーザーに確認しながら進める（一括で全文を書き直して提示するのではなく、セクションごとに確認を挟む）。

## 5. 技術的な注意点

- 既存の `index.html` はbase64画像（ロゴ・チーム写真）が埋め込まれており、Readツールで全文を読むとトークン上限に達する。作業時は `sed` で該当行を `[TRUNCATED]` に置換した一時ファイル経由で読むこと。
- 新規追加する写真はbase64埋め込みにせず、`images/` ディレクトリに実ファイルとして配置し `<img src="images/xxx.jpg">` で参照する。
- 変更後は [[feedback_push_always]] の通り、mainブランチに直接コミット・pushする（現在ブランチ分岐なし、work/mikke-ugc-renewalブランチは放置合意済みで触らない）。
- 変更後、chrome-devtools-mcp等でブラウザ確認を行い、レイアウト崩れ・写真の表示・配色変更が意図通りか確認してからユーザーに提示する。
